> Оновлено 2026-09-14. Це хендовер: усе про AI-агента-консультанта skin.one —
> архітектура, стан, що працює/зламано, як запускати, ключові рішення, наступні кроки.

---

## 1. Що це

AI-агент, що **сам відповідає клієнткам** у Sitniks (на відміну від решти проєкту — аналітики).
Роль — **КВАЛІФІКАТОР, не закривач**: тепло веде клієнтку від звернення до моменту підбору
засобів, потім **передає діалог живим дівчатам-консультантам**. Підбір, ціни, оформлення роблять люди.

**Виняток (важливо):** на прямий запит ЦІНИ конкретного засобу агент **сам дає картку товару**
(назва + опис + ціни по об'ємах) — точно як дівчата. Це не «підбір», а рефлекс-відповідь.

Бренд-персона: «косметолог Анастасія» (обличчя), «Катерина» (волосся). Клієнтка має відчувати
**одну людину від початку до кінця** — жодного «передаю боту/консультанту».

## 2. Git / деплой (КРИТИЧНО для безпеки прода)

- Уся робота агента живе на гілці **`agent-consultant`** (запушена на GitHub). `main` **недоторканий**.
- **Prod (Railway) запускає `python -m src.main`** (`railway.toml`). `main.py` **НЕ запускає** seller/shadow.
  → **Агент-консультант у проді НЕ працює.** Він працює лише **локально** через `run_sitniks_seller.py`.
- Тому деплой будь-чого з `main` агента не зачіпає. `webhook_server.py` (gift-фікс з іншої сесії)
  лишається незакоміченим у робочій теці — для окремого деплою з `main` (НЕ `railway up`, бо той
  затягне локальний код).
- Працюємо на гілці `agent-consultant`. Зміни в robочій теці — не закомічені (комітити за потреби).

## 3. Поточна конфігурація (запуск лише Facebook + питання про ціну)

`.env` / `src/config.py`:
- `AGENT_SOURCES=facebook` — **тільки Facebook** (Instagram/TikTok виключено).
- `SHADOW_MODE=1` — чернетка на підтвердження перед відправкою (безпечний режим).
- `SHADOW_BOT_TOKEN` — заданий, бот **@skinone_shadow_bot**; чернетки йдуть у `TELEGRAM_SHADOW_CHAT_ID`
  (448547265, Дмитро).
- `AGENT_WORKING_STATUS="🤖 В обробці Агентом"`, `AGENT_HANDOFF_STATUS="🔥 Гарячий лід від Агента"`,
  `AGENT_NEW_STATUSES=Новый,...`.
- `HANDOFF_TELEGRAM=0` — передача дівчатам ЛИШЕ через статус (без Telegram-анкети).

**Тригер запуску (нове, 09-14):** бот бере *новий* Facebook-чат **лише якщо клієнтка спитала ЦІНУ**
(`_asked_price` через `is_price_question`). Уже взятий («в обробці») чат — веде далі без обмеження.

## 4. Як працює (потік)

`scripts/run_sitniks_seller.py` крутить у ОДНОМУ процесі: поллер + shadow-бот (кнопки).
1. **Поллінг кожні 25с** (`sitniks_seller.poll_once`) → `connector.get_dialogs(..., chat_filter=_chat_prefilter)`
   (префільтр за джерелом+статусом, щоб не тягнути повідомлення всіх чатів → менше 429).
2. `_bot_should_take(dialog)`: facebook + статус новий/в-обробці + остання репліка клієнтки +
   дівчина не зайшла першою (`_human_replied`) + (для нового) клієнтка спитала ціну.
3. `_claim_chat` → `PATCH /chats/{id}/status` → «🤖 В обробці Агентом» (дівчата бачать, не беруть).
4. `respond()` (engine.py) генерує відповідь: на ціну → картка з `pricecards.find_card` (за adInfo
   реклами або за текстом); інакше кваліфікація; при готовності → `handoff`.
5. **Shadow:** `shadow.request_approval` → чернетка Дмитру з кнопками ✅/✏️/❌.
   - ✅ → `SitniksClient.send_message` шле клієнтці. ✏️ → правиш і шлеш. ❌ → чат дівчатам (статус Гарячий лід).
6. **Handoff (непомітний):** reply порожній, клієнтці нічого; `deliver_handoff` ставить статус
   «🔥 Гарячий лід від Агента». Дівчата розбирають по статусу.

## 5. Sitniks Open API — що з'ясовано (важливо)

| Дія | Стан |
|---|---|
| **Зміна статусу** | `PATCH /open-api/chats/{id}/status` `{"status":"<назва>"}` — **ПРАЦЮЄ** (`SitniksClient.set_chat_status`). `PUT /chats/{id}` статус ІГНОРУЄ. |
| **Відправка** | `POST /chats/{id}/messages` `{"text":..,"attachments":[]}`. **TikTok → 500** (API не шле в TikTok, лише UI). **Facebook → ще НЕ підтверджено жодної успішної відправки!** |
| **Нотатки** | `POST /chats/{id}/notes` `{"text":..}` → **403 forbidden_resource** (токену не дозволено). |
| **Ліміт** | `/messages` max `limit=50` (100 → 400). `PAGE=50` у конекторі. |
| **adInfo (реклама)** | Facebook/Instagram — Є (на «Ціна?» → правильна картка). **TikTok — НЕМАЄ adInfo взагалі.** |
| **client vs manager** | Надійно: `message.sentBy == chat.userId` → клієнт, інакше менеджер (`managerName` часто порожній). Реалізовано в `crm/sitniks.py::_sender_of`. |

## 6. Дані та скрипти

- **Картки цін:** `clients/skin_one.price_cards.md` ← `scripts/mine_price_cards.py` (з реальних
  відповідей дівчат; формат: назва + опис + ціни розпив/оригінал; тримає й набори типу Vita Ion-C).
- **Плейбук:** таблиця Supabase `tone_of_voice` ← `scripts/build_playbook.py` (з good-діалогів;
  `raw_dialog` у БД порожній — тягнеться з Sitniks). Читає `consultant/playbook.py` (qualify_only).
- **Каталог:** `clients/skin_one.products*.md` ← `scripts/build_product_kb.py`.
- **Seller-контекст:** `clients/skin_one.sales.md` (персона, що не називати ціни без картки тощо).
- **Тест локально (без Telegram):** `scripts/chat_with_agent.py` (пиши як клієнтка; `/ad <реклама>`,
  `/reset`). `AGENT_REPLY_DELAY_SECONDS=0` щоб без 15с паузи.
- **Dry-run на реальних:** `scripts/replay_dialogs.py facebook 4 6`.
- **Відкат:** `scripts/revert_bot_claimed.py` — повертає «🤖 В обробці Агентом» у «Новий» (якщо бот
  заклеймив, але не зміг відповісти — напр. TikTok 500 стрендив чати).
- **Тест статусу (оборотний):** `scripts/test_status_change.py <chat_id> "<статус>"`.

## 9. Відкриті питання / наступні кроки

1. **Facebook відправка — головне невідоме.** Треба перший успішний ✅ на реальній Facebook-ціновій
   чернетці. Якщо дійшло — платформа робоча. Якщо 500 (як TikTok) — відправка Sitniks зламана і для
   Facebook → питання до Sitniks, запускати нема сенсу (чати «застрягатимуть» у «в обробці»).
   Рекомендація: **перший прогін контрольовано** (тест-акаунт питає ціну, дівчата хвилину не відповідають).
2. **Гонка з дівчатами.** Дівчата відповідають за секунди, бот полить раз на 25с → часто програє
   (мутекс правильно тримає його осторонь). Щоб реально працювало — або дівчата не чіпають нові
   цінові Facebook-чати першими, або перевести бота на **реакцію по вебхуку** (real-time) — не зроблено.
3. **TikTok — відкладено** (API не шле). Повернути: коли Sitniks додасть TikTok-відправку.
4. Нотатки в Sitniks (резюме на чат) — коли Sitniks відкриє доступ (зараз 403).
